# ProtoPick DOM 导航快捷键设计

## 背景

ProtoPick 当前通过鼠标悬停高亮、点击选取元素。用户需要精确选取某个元素时，如果鼠标悬停到了不理想的层级，只能通过面包屑导航手动点击父/子元素跳转。这个过程需要手离开键盘去操作鼠标，效率较低。

## 目标

增加方向键 DOM 导航功能，让用户可以在 DOM 树中用键盘快速移动焦点，提升元素选取效率。

## 设计方案

### 方案选择：始终跟随焦点（方案 A）

方向键始终作用于当前悬停元素。悬停和键盘共享同一个"当前焦点"，鼠标移动也会更新焦点。

选择理由：ProtoPick 的核心使用场景是快速指向元素，鼠标和键盘应无缝协作。不需要模式切换，认知负担最低。

### 方向键映射

| 按键 | 动作 | 行为 |
|------|------|------|
| `↑` | 父元素 | 移动到当前元素的父元素（与 resolveTarget 逻辑一致，跳过不可见元素） |
| `↓` | 子元素 | 移动到当前元素的第一个有意义子元素 |
| `←` | 前兄弟 | 移动到当前元素的前一个兄弟元素 |
| `→` | 后兄弟 | 移动到当前元素的后一个兄弟元素 |

### 导航逻辑

1. **上（父元素）**：取 `el.parentElement`，如果父元素是 `document.body` 或更上层（html/head），则不动。使用现有的 `resolveTarget()` 逻辑确保跳过不可见/无意义元素。

2. **下（子元素）**：从 `el.children` 中找到第一个通过 `isMeaningful()` 检查的子元素。如果没有有意义的子元素，则不动。

3. **左（前兄弟）**：从当前元素向前遍历 `el.parentElement.children`，找到第一个通过 `isMeaningful()` 检查的前兄弟元素。

4. **右（后兄弟）**：从当前元素向后遍历 `el.parentElement.children`，找到第一个通过 `isMeaningful()` 检查的后兄弟元素。

### 视觉反馈

- **成功移动**：高亮框移到新元素，和鼠标悬停时的橙色虚线框效果一致
- **到达边界**（无父/无子/无兄弟）：当前高亮框边框短暂闪红（200ms），表示无法继续移动

### 边界条件

- **输入框内不触发**：当焦点在 `textarea`、`input` 等可编辑元素中时（如注释输入框），方向键正常编辑文本，不触发 DOM 导航
- **暂停状态不触发**：ProtoPick 处于暂停状态时，方向键不生效
- **到达 body 根节点**：`↑` 不再向上移动，闪红提示
- **无有意义的子元素**：`↓` 不移动，闪红提示
- **无前/后兄弟**：`←` / `→` 不移动，闪红提示

### 面板 UI 更新

底部快捷键提示栏增加方向键提示：`↑↓←→ DOM导航`

## 不做的事

- 不增加"锁定模式"（键盘导航时屏蔽鼠标）
- 不增加"导航历史栈"（和面包屑功能重叠）
- 不修改现有的面包屑导航功能
- 不修改现有的选取/注释/候选区流程
